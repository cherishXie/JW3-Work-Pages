# 剑网三效率工作台

面向多账号、多角色的剑网三任务与收益管理工具。集中管理角色档案、日常与副本排程、执行记录、金币资产和收益分析，支持网页与 Electron 桌面版、本机保存与 JSON 备份。

**[打开 GitHub Pages 工作台](https://cherishxie.github.io/JW3-Work-Pages/)**

无需安装，直接在浏览器访问即可使用。建议收藏上面的完整地址。

[打开 dev 开发版](https://cherishxie.github.io/JW3-Work-Pages/dev/)；日常推送仅更新开发版，稳定页面只在 main 更新时发布。两个地址的浏览器本地存储共用，测试开发版请使用独立浏览器上下文或先备份。

## 桌面版本

源码项目可构建 Windows x64 安装包，以及 Apple Silicon / Intel Mac 的独立 DMG 安装包。桌面版共用工作台业务规则、界面与本地截图识别，数据保存在此电脑；可通过「文件 → 打开本机数据目录」定位。

网页与桌面数据相互独立，目前没有云同步。首次迁移请从网页导出 JSON，再在桌面版「工作台设置 → 数据管理」导入。当前构建没有发布者签名和 Apple 公证。0.2.1 起，界面与业务资源支持应用内检查并点击更新；原生壳升级需安装对应平台的安装包。

## 主要功能

| 功能 | 可以做什么 |
| --- | --- |
| 总览与收益分析 | 查看任务进度、排程预测、历史实测、收益占比、时薪与 ROI，对比币价、点卡成本和并行配置 |
| 账号与角色 | 维护账号、区服、角色、等级、门派、心法、定位与侠客资料，管理任务参与资格 |
| 日常与副本安排 | 按“任务类型 → 任务与范围 → 组队配置 → 阵容复核”四步安排任务，支持副本多选、路线排序和队伍复用 |
| 组队与资格检查 | 检查同账号互斥、区服、角色资格、职责、侠客与 CD，显示未安排原因，支持调整成员 |
| 排程与执行 | 按日期查看批次，保存执行草稿、计时、登记完成，记录或补录金币收益与耗时 |
| 角色查漏与历史 | 按角色、账号和任务检查周期进度，查看任务历史、每周轨迹与副本 CD |
| 金币与装备资产 | 按采集、本周 / 上周、本月 / 上月及自定义时间查看账号与角色金币变化，支持余额历史、流水转账、观测修正、装备与实际现金 |
| 截图识别 | 在浏览器本地识别角色截图，核对后更新资料与余额；识别结果需要人工确认 |
| 数据备份与交换 | JSON 导入预览、合并或替换、完整备份、日期档案、角色 CSV 与操作撤销 |
| 分享与外观 | 导出 PNG 战报，可隐藏账号、角色和区服；提供五种主题，适配桌面与手机 |

## 开始使用

1. 首次打开按引导创建账号和角色，也可以先进入体验模式了解页面。
2. 在任务配置中确认参与角色、收益、耗时、刷新周期与计价参数。
3. 在任务中心安排日常或副本，复核阵容后保存排程。
4. 执行时登记每批完成情况，按实际情况填写或补录收益、操作时间与账号在线时间。
5. 在总览、历史分析与资产台账查看结果，定期导出 JSON 备份。

确认排程不会自动产生收益。仅登记完成而未填写收益或耗时的记录会保留待补状态；预测与实测应分开理解，ROI 依赖实际填写的参数与数据。

## 数据保存与隐私

- 网页业务数据保存在当前浏览器的本地存储中，桌面版保存在本机应用数据目录；站点不会自动上传账号、角色、截图或备份文件到 GitHub。
- 不同浏览器、设备和访问地址使用独立的数据区。换设备、换地址或清理浏览器数据前，请先导出 JSON，再在目标环境导入。
- 支持按北京时间保存每日快照与导出全部日期档案；本地快照不能替代外部备份。网页普通保存不会自动回写导出的 JSON 文件；桌面版自动写入自己的应用数据文件。
- 截图识别在本地进行，文字和金额仍需人工核对。分享战报前请检查隐私选项。
- 这是辅助规划与记账工具。游戏规则、角色资格、CD 与收益参数需按实际情况维护；目前不会自动启动模拟器、登录游戏或执行游戏操作。

## 本地运行

在已安装 Node.js 的环境中，于项目目录执行：

```sh
npm start
```

打开 [本地工作台](http://127.0.0.1:4173)。dev 与 main 均包含 npm 开发、验证与打包脚本，日常开发在 dev 进行。

## 桌面开发与构建

需要 Node.js 22.12+，在公共仓库 dev 分支执行：

```sh
npm ci
npm run desktop
npm run dist:mac
npm run dist:win
```

产物在 `release/`，包括 Windows x64 `.exe`、macOS arm64 / x64 各自的 `.dmg`。安装包上传到公共仓库的 Releases 附件，不进入网页分支；公共仓库自动生成的 Source code 压缩包仅包含静态网页，不是桌面安装包。

## 开发与发布

以下命令在公共仓库 dev 分支执行：

```sh
npm test                     # 运行规则与数据验证
npm run build:pages          # 生成经过白名单检查的 .pages-dist 静态产物
npm run publish:pages:public # 验证并推送 dev，触发独立开发页面与客户端发布
```

正式发布执行 `npm run release:main`，通过版本与构建检查后将 dev 快进至 main。GitHub Actions 将两个频道的静态快照合并部署，稳定版在根目录，开发版在 dev/，互不覆盖；客户端使用工作流的受限 GitHub token 发布。

公开源码与网页产物均使用显式白名单，不包含私有仓库历史、个人数据、备份、凭据或 `data/`、`output/`、`docs/` 目录。

正式版本的更新内容记录在 [CHANGELOG.md](CHANGELOG.md)。

## 安装与版本更新

网页支持 PWA：首次联网打开完成缓存后，可从支持的浏览器菜单安装到设备，并可离线重新打开及识别截图。PWA 安装入口由浏览器提供，不申请系统通知权限；更新通知显示在工作区顶部。

网页和 0.2.1 起的 Electron 会在启动、返回前台、恢复网络时检查更新，使用期间每十分钟再检查。底部提供「检查更新」。发现新版本后可选择「立即更新」或「稍后」。更新先完整下载、校验资源，点击后切换并重新打开工作台；不会删除账号、角色、备份或主题。编辑窗口、未保存的排程或存储错误会阻止切换，请先保存或处理后重试。离线或校验失败时继续使用现有版本。

网页的 main 与 dev 使用不同的 Service Worker 范围及版本缓存。其他已打开的标签页继续使用各自固定的版本，刷新后才切换。两个地址依然同源，共用浏览器业务数据，开发验证请使用独立上下文。

Electron 将更新资源保存在应用数据目录的 updates/ 中，不替换业务存储文件。下载校验失败时保留旧版；新资源未能正常启动时回退。此功能更新的是界面与业务资源，不替换 Electron 引擎或原生主进程。如果更新要求新原生能力，将提示下载对应平台的新安装包。0.2.0 及更旧客户端没有更新能力，需要先安装一次 0.2.1；之后日常资源更新可直接点击完成。
